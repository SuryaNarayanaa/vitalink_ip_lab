# Source inconsistencies and recommended improvements

These are documentation-relevant discrepancies found while comparing source areas. They are not silently resolved as implementation changes.

## INC-01: Backend admin enrollment is not handled by Flutter login

The backend can return `auth_status: TOTP_ENROLLMENT_REQUIRED` and implements `/auth/login/totp/enroll/setup` plus `/activate`. The Flutter `AuthRepository.login` only handles `OTP_REQUIRED` and `TOTP_REQUIRED`; it otherwise tries to parse the response as an authenticated session. `AppStrings` also has no enrollment endpoint constants.

**Impact:** production/staging unenrolled administrators can reach a backend-supported enrollment state that the current client cannot complete.

**Recommended improvement:** add client models, endpoint constants, repository methods, UI flow, and tests for password-bound enrollment; retain backend security/lockout/challenge behavior.

## INC-02: Deployment target drift

Backend CD targets EC2 and `/opt/vitalink`; Flutter defaults/APK builds and Vercel rewrites target `https://vitalink-uimf.onrender.com`; Flutter web has GitHub Pages and Vercel deployment instructions.

**Impact:** an artifact can call a different backend than the one just deployed, and source cannot identify production.

**Recommended improvement:** declare an environment inventory and make client API origin an explicit protected build input for every release.

## INC-03: Checked-in Nginx does not enable TLS

The active server listens on HTTP. Redirect and TLS blocks are commented, although 443 is published and certificates are mounted.

**Impact:** the EC2 design alone does not prove encrypted public transport.

**Recommended improvement:** document/validate upstream TLS termination or enable certificates, redirect, HSTS, and renewal in the actual edge configuration.

## INC-04: Multiple health definitions

The backend Dockerfile healthcheck calls `/`, while Compose and CD use `/health/ready`.

**Impact:** a standalone image can be marked healthy without MongoDB/config/provider-worker readiness.

**Recommended improvement:** use `/health/ready` for deployment readiness and reserve `/health/live` for liveness consistently.

## INC-05: Migrations are outside CD

The backend defines eight migration commands, but backend CD deploys and health-checks without a migration job or compatibility gate.

**Impact:** legacy documents can fail exact auth, tenant, file, device, or policy predicates after code rollout.

**Recommended improvement:** add an environment-specific, approval-gated migration phase with dry-run evidence and rollback compatibility checks.

## INC-06: Monitoring is diagnostic, not operationally complete

The backend has sanitized logs, optional Loki, readiness, in-process counters, and durable outbox state, but no committed dashboards, alerts, tracing, error tracker, SLOs, or rota.

**Impact:** serious readiness, audit-gap, dead-letter, provider, or tenant-denial patterns may not page an owner.

**Recommended improvement:** implement durable metrics/alerts and link them to named runbook owners.

## INC-07: Deployment-script test file contains repeated suites

`deploy/deploy.test.sh` contains repeated definitions of the same JWT-secret validation fixtures/tests and is not called by GitHub Actions.

**Impact:** maintenance noise and false confidence about deployment preflight coverage.

**Recommended improvement:** deduplicate the file and run it in backend/deployment CI.

## INC-08: ML artifacts are incomplete and disconnected

`ml-service/main.py` only prints a greeting; `ml_pipeline` tracks compiled Python bytecode without source; no application route or repository calls it.

**Impact:** the repository contains model/data artifacts that can be mistaken for a production clinical feature.

**Recommended improvement:** remove generated bytecode from Git, document research artifacts, or add a separately reviewed/validated service architecture before integration.

## INC-09: OpenAPI drift existed for two authentication routes

The two password-bound TOTP enrollment routes were absent from the existing OpenAPI file, and `TOTP_ENROLLMENT_REQUIRED` was absent from the challenge enum.

**Resolution in this documentation change:** the OpenAPI contract now includes both operations and enum state; route parity is a blocking validation.

## INC-10: No repository-backed backup/restore implementation

Deployment and migration guidance assumes operators can establish a restore point but provides no backup schedule or restore test.

**Impact:** application rollback cannot recover incompatible or destructive data changes by itself.

**Recommended improvement:** add provider-specific backup/restore automation, encrypted retention, RPO/RTO, and recurring restore verification.
