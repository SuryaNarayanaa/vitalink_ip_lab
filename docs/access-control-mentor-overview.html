VitaLink Admin · Access Control

What Application Admins can do in Access Control (RBAC V2). This page manages administrator capabilities only — not Doctor or Patient clinical rights.

Mentor overview
Role 1 · Platform

Application Admin

Global platform authority. Full platform capabilities (hospitals, admin accounts, policies, audit, analytics, billing, config, health, broadcast).

  • Open Access Control and review all policies
  • Edit Hospital Admin and System Auditor policies
  • Preview changes, save with a change reason, restore history
  • Invite and manage other administrators (separate Accounts page)
Policy is LOCKED — cannot toggle Application Admin capabilities in the UI
Role 2 · Tenant

Hospital Admin

One assigned hospital. Operational authority only inside that tenant.

  • Doctors: list, create, update, status, credential reset
  • Patients: list, onboard, assign/reassign, status, credential reset
  • Hospital dashboard, analytics, audit (tenant-scoped)
  • Billing read / checkout for own hospital invoices
  • Tenant notification broadcast & operations health
EDITABLE policy — App Admin can turn tenant capabilities on/off
Role 3 · Oversight

System Auditor

Global, hard read-only. Mutations are blocked even if a policy were misconfigured.

  • View Access Control policies and history (read-only)
  • Configurable global reads: audit, billing (and optionally others)
  • Cannot create users, change policy, or broadcast
  • Must not be assigned to a hospital
EDITABLE capability map — but role remains read-only at runtime

What Access Control UI lets App Admin do

1
Review hierarchy See fixed roles: App Admin, Hospital Admin, System Auditor
2
Inspect policies Version, last change reason, active account counts, capability lists
3
Edit & preview Toggle Hospital Admin / Auditor capabilities, preview impact
4
Save or restore Apply with change reason; restore a prior policy revision from history

Hospital Admin capability groups

  • Dashboard · Doctors · Patients · Assignments
  • Account status · Credential reset
  • Tenant audit · Analytics · Billing
  • Notifications · Operations health

System Auditor capability groups

  • Global audit (typical default: on)
  • Global billing read (typical default: on)
  • Optional: hospitals, analytics, health, policy read
  • No write/mutation capabilities

Explicit non-goals

Not managed here

  • Doctor clinical permissions (fixed by clinical rules)
  • Patient self-service permissions (fixed)
  • Application Admin capability matrix (protected / locked)
  • Creating doctor/patient accounts (use Doctors / Patients pages)
  • Creating admin users (use Administrator Accounts)

Who can open this page

  • Application Admin — view + edit editable policies
  • System Auditor — view only
  • Hospital Admin — cannot open Access Control
